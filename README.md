# Steel_Connect

POSCO K-뉴딜 아카데미 2026 내부 해커톤 프로젝트.
대주제: "AI로 더 안전하고, 멈추지 않고, 더 정확하게 생산하는 제철소를 만들어라"

## 한 줄 주제
수소환원제철 전환에서 **탄소를 어떻게 더 효율적으로 줄일 수 있나**를 시나리오(what-if)로 계산하고, LLM 어시스턴트가 그 계산을 근거와 함께 답한다. "예측"이 아니라 "시나리오"다.

## 문제 정의
- 고로에서 전기로·수소환원제철로 전환하면 쇳물 1톤당 전력이 크게 늘어난다. 수소환원은 문헌 기준 약 3.5~3.7 MWh/t로 전기로(약 0.45 MWh/t)의 8배 안팎이다.
- 그 전력이 탄소를 많이 내는 전력망 전기라면 저감 효과가 줄어든다. 논문(Bhaskar 2020)은 전력배출계수 0.456 tCO2/MWh를 넘으면 수소환원이 배출을 오히려 늘린다고 밝힌다. 한국의 2023년 값은 0.4173이다.
- "어떤 경로를, 얼마나 깨끗한 전력으로 하면 탄소를 효율적으로 줄이나"를 빠르게 묻고 근거 있는 답을 받을 도구가 없다.

## 구성
1. **시나리오 시뮬레이터** (`src/simulator.py`): 전기로·수소환원 규모, 가동률, 무탄소 전력 비율, 요금제 등을 바꾸면 추가 전력, 탄소(Scope 1 감축과 Scope 2 증가), 요금이 나온다. 허용 범위 밖 값은 `ValueError("... 근거 없음")`으로 거절한다.
2. **그린 수소 vs 전력망 전기 추천** (`src/hydrogen.py`의 `h2_supply`): 수소환원의 수소를 재생에너지 직접PPA로 만들지(그린 수소) 한전 전력으로 만들지 비교하고, 탄소 가격·PPA 단가·전력배출계수·감축 목표·확보량에 따라 어느 쪽이 나은지와 갈림길 값을 돌려준다. 숫자는 `simulate`에서 나온다.
3. **LLM 어시스턴트**: 질문 → 시나리오 변수 → 시뮬레이터 계산 → 근거 인용 답변. 계산은 코드, 해석은 LLM이 한다. 평가 지표는 숫자 일치율, 인용 정확도, 근거 없는 질문 거절률이다.

## 핵심 결과
- 같은 100만 톤을 만들 때 전력 1 MWh당 탄소 저감은 전기로가 수소환원(전력망 전력)의 약 33배다(고로 Scope 1 1.99 t/t 기준의 같은 경계). 포스코 주장 순감축 1.4 t/t로 바꾸면 약 26배다.
- 수소환원이 전기로(고철)만큼 줄이려면 무탄소 전력 비율이 약 83% 필요하다(같은 경계 상향식). 포스코 주장 순감축 1.4 t/t 기준이면 약 62%다. 두 값은 경계 가정에 따른 시나리오이며 신뢰구간이 아니다.
- 한국 전력배출계수는 2018년 0.5404에서 2023년 0.4173으로 내려왔다. 이 추세로 2028~2030년의 필요 무탄소 비율을 시나리오 범위로 본다.
- 그린 수소 vs 전력망 전기(수소환원 수소, 기본 조건: 배출계수 0.4173, 태양광 PPA 180원/kWh, K-ETS 29,500원/t): 전력망이 쇳물 1t당 약 6.5만 원 싸지만 1t당 1.12 tCO2를 더 낸다(순 저감 0.44 t 대 1.55 t).
  - **그린 수소가 좋은 경우**: 탄소 가격이 약 8.7만 원/t 이상(EU ETS 13.2만 원 수준이면 그린), PPA 계약 단가 157원/kWh 이하(정부 태양광 목표 150원이면 K-ETS 시세에서도 그린), 배출계수 0.535 이상(전력망 수소가 고로보다 나쁨), 쇳물 1t당 0.44 t보다 큰 감축 목표.
  - **전력망 전기가 좋은 경우**: 탄소 가격이 낮고(현재 K-ETS) PPA가 비쌀 때, 재생에너지 확보량이 모자랄 때(100만 t에 2.68 TWh/년 필요), 전력망이 깨끗해질수록. 수전해를 경부하에만 돌리면 전력 단가가 177원에서 140원/kWh로 내려가지만 설비가 1.94배 필요하다.
  - 2025 실적(전력거래소 시간별 자료)으로 보면 경부하(밤) 전력은 연평균보다 0.7% 더 탄소가 많고 정오가 가장 깨끗하다(0.92배). 경부하 운전은 요금만 줄이고 탄소는 줄이지 못한다.
  - 같은 시간에 난 재생에너지만 인정하는 "시간 일치" 기준이면 태양광 PPA는 수전해 전력의 47%(풍력 69%, 반반 72%)만 채워, 그린 수소의 1t당 순 저감이 1.55 t에서 0.94 t(반반 1.22 t)로 준다.
- 한 문장: 수소환원의 탄소 효과는 전력이 얼마나 깨끗한가가 결정하고, 그린 수소의 값어치는 탄소 가격이 결정한다.

## 폴더
```
src/        모듈화한 함수 (simulator, load_profile, sensitivity, emission_factor, hydrogen, ext_data, eda 등)
analysis/   분석 실행본(.py). 노트북(.ipynb)은 git 제외
data/       데이터셋과 근거 PDF (git 제외)
figures/    그림 (git 제외)
reports/    변수표, 보고서 (git 제외, 일부 md 예외)
```

## 실행
프로젝트 루트에서 실행한다. 필요 패키지: pandas, numpy, matplotlib (PDF 표 추출은 pypdf).
```
python3 -m src.simulator                       # 시나리오 S0~S5 결과 출력
python3 analysis/01_부하분석.py                 # UCI 부하, 요금 개편, 최대부하 이동
python3 analysis/03_부하지속곡선.py             # 부하지속곡선, 최대수요 관리
python3 analysis/04_민감도분석.py               # 토네이도, 몬테카를로
python3 analysis/05_검증.py                     # 내부 정합성 assert + 외부 수치 대조
python3 analysis/06_경로비교.py                 # 전기로 vs 수소환원 경로 비교
python3 analysis/07_배출계수_손익분기지도.py     # 전력배출계수 추세와 손익분기 지도
python3 -m src.hydrogen                        # 그린 수소 vs 전력망 전기 추천(기본 조건)
python3 analysis/15_그린수소_전력망_추천.py      # 상황별 추천 지도와 손익분기 탄소 가격 곡선
python3 -m src.eda                             # EDA 요약(데이터 목록·품질·UCI·Factbook). 노트북 analysis/00_EDA.ipynb가 src/eda.py·src/ext_data.py 함수를 부른다(노트북은 git 제외)
python3 analysis/16_외부데이터_시간대배출_재생.py  # 외부 공개 데이터(data/의 kpx_*·epsis_*·icap_*)로 시간대별 배출계수·시간 일치율·탄소 가격 범위 재계산
(cd web && npm install && npm run build)        # 웹 화면(React + COMPASS) 빌드. 처음 한 번, 화면을 고친 뒤에도
python3 -m src.web --llm claude_code           # 웹 화면(http://127.0.0.1:8000). 내 PC의 Claude Code 로그인으로 AI 연결, API 키 불필요. 빌드가 없으면 옛 화면(web/legacy.html)
python3 -m src.web                             # 웹 화면, 키가 있으면 그 연결(ANTHROPIC_API_KEY 등), 없으면 계산기만
```
`data/Steel_industry_data.csv`(UCI Steel Industry Energy Consumption)는 저장소에 들어 있다.

**Claude Code 연결(`--llm claude_code`)**: `claude` 명령이 설치·로그인된 PC에서만 된다. 모델은 `claude-sonnet-5-5`(`CLAUDE_MODEL`로 변경). Claude Code는 계산 도구 8개(`src/assistant_mcp.py`)만 쓸 수 있고 Bash 등 내장 도구는 꺼져 있다. 구독 사용량이 질문마다 차감되고 응답에 십수 초 걸린다.

## 데이터와 근거
- UCI Steel Industry Energy Consumption (2018, 15분 간격 35,040행): 요금 시간대와 부하 형태 분석. 광양 소규모 사업장이라 제철소 대표가 아니고 방법 시연용이다.
- 포스코 ESG Factbook 2024: 구매 전력, Scope 1·2.
- 한전 산업용(을) 요금표 2025-04와 2026 개편 공식 요금표·시간대표(2026-03-13·16), 기후에너지환경부 전력배출계수(2023 확정 0.4173). 요금 시간대는 공식표를 쓰고, UCI 원본의 시간대 라벨(2018 옛 시간대)은 쓰지 않는다.
- 수소·전력 시장: IEA Global Hydrogen Review 2025(수전해 효율), 국내 그린수소 생산원가(2026-10 보도), 직접PPA 단가·부대비용(보도·KSES 논문·전력거래소), K-ETS·EU ETS 시세(2026-11-09).
- 외부 공개 데이터(`data/kpx_*.csv`, `data/epsis_*.json`은 git 추적. `data/icap_systems.json`은 ICAP 약관상 재배포 금지라 git 제외, 받는 법은 `analysis/16` 맨 위): 공공데이터포털 전력거래소 2025 연료원별 시간대별 전력거래량·시간별 신재생 발전량과 설비용량·지역별 시간별 태양광·풍력, ICAP Allowance Price Explorer(K-ETS·EU ETS 일별), EPSIS 연도별 판매단가. 계산 결과는 코드 상수(`src/emission_factor.py`, `src/hydrogen.py`)로 넣었고, 원본이 있으면 `analysis/05_검증.py`가 다시 계산해 대조한다.
- 논문: Vogl 2018, Bhaskar 2020 (수소환원 전력 원단위).
- 변수별 출처와 신뢰도는 `reports/결과보고서.md` 부록 E-1에 정리한다.

## 한계 (숨기지 않고 밝힌다)
- 수소환원 전력 원단위와 고로 배출은 유럽 논문과 포스코 평균에서 가져온 값이다. 포스코 실측이 아니다.
- 포스코 사내 에너지 시스템은 알 수 없다. 현업 적용은 기존 시스템을 대체하지 않는 보완 계층과 그림자 운전(실제 운영과 나란히 돌려 비교만 하는 방식) 로드맵으로 설명한다.
- 고철 공급 한계와 설비 투자비는 반영하지 않았다. 전력배출계수 단년도 값은 참고용 산출이다.
- 그린 수소 비교는 연간 전력량 기준이다(재생에너지와 수전해 시간 일치·저장 미반영). 수전해 설비비는 두 방법이 같다고 보고 뺐고, 경부하 운전·구매 그린수소는 참고로만 보여 준다. PPA 망이용료는 위치·전압마다 달라 논문 예시값을 썼다.
- 시간대별 배출계수는 전력시장 거래 발전기만(지붕 태양광·한전 PPA 제외) 본 평균 믹스 기준이라 낮 시간이 실제보다 높게 나올 수 있고, 추가 수요에 반응하는 한계 배출은 아니다. 시간 일치율은 전국 시장 참여 태양광·풍력 합산 프로필이라 특정 발전소와 다를 수 있다.
- 시뮬레이터의 "숫자 일치율"은 시뮬레이터 출력과 비교하므로 시뮬레이터 자체의 타당성을 증명하지 않는다. 검증은 `analysis/05_검증.py`로 따로 한다.
