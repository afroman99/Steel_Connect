# 결과보고서 — 전환기 전력·요금·탄소 시나리오 시뮬레이터와 AI 어시스턴트 (Steel Connect)

> 팀 [팀명 기입] · 2026-11-09 (초안)
> 데이터: 공개 자료(UCI 철강 에너지 데이터, 한전 요금표, 포스코 ESG Factbook 등). **사내 데이터는 쓰지 않았다.**
> 숫자는 모두 **기본값(2026년 요금 개편 후, 전력배출계수 0.4173)** 기준의 **조건부 시나리오**이며 예측이 아니다.
> `[기입]`, `[평가 후]` 표시는 아직 값이 없는 곳이다. 제출 전에 채우거나 지운다.

**요약**
- 고로를 줄이고 전기로·수소환원제철로 전환할 때의 **전력, 요금, 탄소**를 what-if(이렇게 하면 어떻게 되는가)로 계산하는 시뮬레이터를 만들고, 자연어 질문을 이 계산기에 잇는 **AI 어시스턴트**를 붙였다. 숫자는 검증된 코드가 만들고, AI는 질문을 이해해 계산기를 부르고 결과를 설명한다.
- 신규 전기로(250만 t 설비, 가동률 70%)는 추가 구매 전력 **0.79 TWh**, 연 전력요금 **1,402억 원**, **순 저감 301만 tCO2**다. 수소환원(30만 t 설비)은 전력망 전력이면 순 저감이 9.2만 t에 그치고, 무탄소 전력 100%면 41.8만 t이다. 전력 1 MWh당 순 저감은 전기로가 수소환원(전력망)의 약 **33배**다.
- 쓰임새는 **목표 순 저감량 → 필요한 무탄소 전력 → 확보량 대비 부족분 → 부족분을 메우는 조건**이다. 예를 들어 수소환원 50만 t/년으로 순 저감 50만 t을 내려면 무탄소 전력이 36.2%(0.67 TWh) 필요하고, 0.3 TWh만 확보했다면 부족한 0.37 TWh를 메울 조건 여섯 가지(확보량, 목표, 생산량, 전기로 전환, 전력 원단위, 배출계수)를 한 조건씩 역산해 보여 준다.
- 경제성은 **증명하지 않는다.** 고로가 줄면 자체발전(부생가스 발전)도 줄어 구매 전력이 늘고, 전력비용만 놓으면 손익분기 배출권 가격(4.7만 원/t 이상)이 가정 범위(1만~3만 원/t)를 넘는다. 설비 투자비와 원료비 절감이 빠져 있어서, 성립 조건을 제시하는 결과로 읽어야 한다.
- 평가는 질문 33개(정상 18, 정보 부족 8, 범위 밖 7)로 한다. 결과: [평가 후]
- AI 연결은 Claude Code(`claude -p`)를 엔진으로 쓴 **로컬 시제품**이다(Claude API 직접 호출이 아님). 개발자 PC에서만 동작한다.

## 1. 문제 정의

- **대주제**: AI로 더 안전하고, 멈추지 않고, 더 정확하게 생산하는 제철소. 우리는 **정확하게**(근거 있는 숫자)와 **멈추지 않고**(전력 확보 병목을 미리 보기)에 맞췄고, 안전은 억지로 연결하지 않았다.
- **상황**: 고로를 줄이고 전기로·수소환원제철로 가면 전력 사용이 늘고, 부생가스로 만들던 자체발전은 줄어든다(포스코 ESG 에너지 페이지 원문). 얼마나 더 필요하고 비용과 탄소가 어떻게 달라지는지 빠르게 따져 볼 도구가 필요하다.

| 항목 | 내용 |
|---|---|
| 분석 목적 | 전환 시나리오별 전력·요금·탄소를 계산하고, 목표 감축량을 정하면 필요한 무탄소 전력과 부족분, 부족분을 메우는 조건을 알려 준다 |
| 형태 | 계산 엔진(시뮬레이터) + 자연어 질문을 계산기에 연결하는 AI 어시스턴트 |
| 원칙 | **계산은 코드, 해석은 AI.** 숫자는 AI가 만들지 않는다. 예측이 아니라 시나리오다 |
| 쓰는 사람(제안) | 설비 전환 담당자(목표·생산량 입력), 에너지 조달 담당자(확보 예정 전력량 입력). 실제 업무 방식은 현업 인터뷰로 확인해야 한다 |

## 3. 부하·요금 분석

UCI 부하 데이터로 한전 요금의 시간대 구조(경부하·중간부하·최대부하)가 평균 단가에 미치는 영향을 계산했다.

- 요금은 전력량요금(계절·시간대별), 기본요금(계약전력), 기후환경·연료비조정요금, 전력산업기반기금(2.7%)을 합한다. 요금제는 고압 A·B·C와 선택 Ⅰ~Ⅲ의 9종이다. 광양 규모는 154kV 이상·월 500시간 초과 가동(B3)으로 가정했다.
- 2026 시간대 개편(11~12·13~15시 중간부하, 18~21시 최대부하, 봄가을 주말 11~14시 50% 할인)을 반영하면 UCI 사이트 기준 연 청구액이 약 3.75% 줄고, 단가 조정이 가장 큰 요인이다. 신규 전기로(S1) 요금은 1,414억 원에서 1,402억 원으로 약 0.9% 낮아진다.
- 최대부하를 옮기는 효과는 수확 체감(옮길수록 이득이 줄어드는 현상)이 있다. 부하지속곡선으로 최대수요 관리의 가치도 살펴봤다.
- 민감도 분석(토네이도: 한 변수씩, 몬테카를로: 전 변수 동시)을 했다. 몬테카를로의 비율은 가정한 분포에서의 표본 비율이지 현실의 확률이 아니다. 자체발전 감소율은 근거가 약하고 결과를 지배해서 불확실성이 아니라 **시나리오 축**으로 분리했다.

## 4. 계산 엔진과 AI 어시스턴트 (모델링에 해당)

**4.1 구조**
```
질문 → [AI 어시스턴트] → [계산 도구 7개] → 결과(JSON) → [AI 설명 + 근거 인용]
         (이해·설명)       (코드가 계산)      status: ok / ask / refuse
```
- 계산 도구: ① 시나리오 계산 ② 목표를 달성하는 필요 생산량 역산 ③ 필요 무탄소 비율·부족분 ④ 조건 하나씩 바꿔 반복 ⑤ 경로 비교 ⑥ 수소환원 손익분기 배출계수 ⑦ **부족분을 메우는 조건 역산(`close_gap`)**
- 입력이 허용 범위를 벗어나면 계산하지 않고 거절한다(`refuse`). 생산 규모나 목표가 없으면 추측하지 않고 되묻는다(`ask`). 근거가 없는 질문(미래 예측, 사내 실제 데이터, 투자비, 실제 배출권 회피액, 시간대별 생산 지속 여부)은 도구를 부르지 않고 거절한다.
- 파인튜닝(모델을 새로 학습시키는 일)은 하지 않았다. 숫자를 AI가 외울 필요가 없고, 30여 개 질문으로는 학습이 되지도 않으며, 숫자가 틀어질 위험만 커진다.

**4.2 계산 엔진의 핵심 규칙**
- 전기로 순 저감 = 고로 Scope 1 원단위 1.99 − 전기로 직접 배출 0.08 − 구매 전력 × 배출계수(상향식 같은 경계). 포스코 주장 1.4 t/t는 경계 미확인이라 별도 시나리오(S1P)다.
- 수소환원 순 저감 = 고로 대체 1.99 − 잔여 배출 − 전력 원단위 × 배출계수 × (1 − 무탄소 비율).
- 자체발전 감소: 고로가 줄면 그만큼을 전력망 구매로 대체한다(`selfgen_cut`, 시나리오 축).
- 시나리오 8개: S0(전환 없음), S1(전기로), S1P(포스코 주장 경계), S1O(개편 전 요금), S2(자체발전 15% 감소), S4(수소환원, 전력망), S4G(수소환원, 무탄소), S5(전기로+수소환원).

**4.3 AI 연결**
- Claude Code(`claude -p`)를 AI 엔진으로 연결한 로컬 시제품이다. 모델은 Claude Sonnet 5.5로 고정했다. 계산 도구를 부르는 명령 하나만 허용하고 파일 수정과 웹 도구는 막았다.
- 연결부(`ask()` 한 곳)만 바꾸면 Claude API나 사내 LLM으로 옮길 수 있다.
- 한계: 개발자 PC의 Claude Code 로그인을 쓰므로 그 PC에서만 동작한다. 시연은 영상과 현장 시연으로 보인다. 응답은 질문당 십수 초 걸린다.
- 웹 화면: [팀원 작업 결과 기입]

**4.4 검증**
- `analysis/05_검증.py`가 내부 정합성, 요금(S1 178원/kWh 대 산업용 평균 판매단가 181.9원), 전기로 감축 규모, Scope 2 역산, 총 전력 역산을 확인한다.
- 질문 정답은 계산기 결과이고, 정상 질문 일부는 계산기를 쓰지 않은 손계산으로 한 번 더 대조했다(독립 검증).

## 5. 핵심 결과

**5.1 신규 전기로(S1: 250만 t 설비, 가동률 70% = 175만 t)**
| 항목 | 값 |
|---|---|
| 추가 구매 전력 | 0.79 TWh (현재 구매 전력의 +25.8%) |
| 연 전력요금 | 1,402억 원 (178원/kWh) |
| Scope 2 증가 / Scope 1 감축 | +32.9만 t / −334만 t |

|---|---|---|
| 전력망 전력 | 0.78 TWh | 9.2만 t |

| 수소환원(전력망) | 228만 t | 8.5 TWh |
| 수소환원(무탄소 50%) | 82만 t | 3.1 TWh |
| 수소환원(무탄소 100%) | 50만 t | 1.9 TWh |

**5.5 필요한 무탄소 전력, 부족분, 메우는 조건** (수소환원 50만 t/년, 목표 순 저감 50만 t)
필요 무탄소 비율 **36.2%**, 필요 전력량 0.67 TWh. 확보량이 0.3 TWh이면 0.37 TWh가 부족하다. 한 번에 한 조건만 바꿔 부족분을 0으로 만드는 값은 다음과 같다.
| 구분 | 바꿀 조건 | 현재 → 필요 |
|---|---|---|
| 결정 | 무탄소 확보량 | 0.3 → 0.67 TWh |
| 결정 | 목표 순 저감 | 50만 → 34.4만 t |
| 결정 | 수소환원 생산량(같은 목표를 더 큰 규모로) | 0.5 → 0.86 백만 t |
| 결정 | 전기로로 전환 | 0.29 백만 t이면 같은 목표 달성(전력 0.13 TWh) |
| 외부 조건 | 전력 원단위(기술) | 3,720 → 2,972 kWh/t |
| 외부 조건 | 전력배출계수(전력 믹스) | 0.4173 → 0.3173 |
"결정"은 우리가 정할 수 있는 것, "외부 조건"은 기술·정책에 달린 것이다. 생산량을 늘리면 필요량이 줄어드는 것은 같은 목표를 더 큰 규모로 나누면 톤당 필요 감축이 줄기 때문이다. 조건을 동시에 바꾸는 조합은 계산하지 않았다.

**5.6 자체발전 감소와 경제성**
| 자체발전 감소율 | 추가 구매 전력 | 전력비용 | 순 저감 | 손익분기 배출권 가격 |
|---|---|---|---|---|
| 0% | 0.79 TWh | 1,402억 원 | 301만 t | 약 4.7만 원/t |
| 5% | 1.69 TWh | 3,000억 원 | 264만 t | 약 11.4만 원/t |
| 15% | 3.48 TWh | 6,196억 원 | 189만 t | 약 32.8만 원/t |
(전기로 S1 기준. 손익분기 = 전력비용 ÷ 순 저감. 수소환원은 감소율 5%에서 순 저감이 음수가 된다.)
가정한 배출권 가격 범위는 1만~3만 원/t이므로, **전력비용만 보면 배출권 수익으로는 전력비용을 덮지 못한다.** 설비 투자비와 고로 원료비 절감은 반영하지 않았다. 따라서 "전환이 경제적이다/아니다"가 아니라, 성립하려면 배출권 가격이 얼마 이상이어야 하고 자체발전 감소가 얼마 이하여야 하는지를 보여 주는 결과다. 이 결과를 숨기기 위해 자체발전을 빼는 방식은 쓰지 않았다.
※ "대체 생산량 ÷ 조강 35 Mt 비례"로 잡은 참고 감소율은 전기로 약 5%, 수소환원 약 0.6%이며, 근거가 약한 단순 가정이다.

## 7. 현업 적용 해석

- 우리는 포스코 사내 에너지 시스템과 데이터를 모른다. 그래서 기존 시스템을 대체하지 않고 그 위에 얹는 **보완 계층**으로 제안한다.
- **계산기와 평가 질문은 그대로 가져가고, AI 연결부와 입력 데이터만 사내 것으로 교체**한다.
- 처음에는 사내 계산과 나란히 돌려 결과를 비교하는 **그림자 운전**으로 시작해 신뢰를 쌓은 뒤 쓰임새를 넓힌다. 이때 33개 질문이 모델 교체 때의 수락 시험(같은 시험을 다시 통과하는지 보는 확인)이 된다.
- 사내 확장 시 교체할 입력: UCI 부하 → 설비별 실측 부하, 공개 요금표 → 실제 계약·청구, 문헌 원단위 → 설비 실측, 전국 평균 배출계수 → 사내 전력 조달 구성. 사내 사양은 확인된 것이 아니라 확장 방향이다(부록 E-7).

- **작업 방식**: 계산 로직은 한 사람이 책임지고 만들어 일관성을 지켰고, 나머지는 근거 대조·질문 검토·평가·화면으로 나눠 맡았다. 새 분석은 노트북에서 탐색한 뒤 `src/` 함수, `analysis/` 실행본 순서로 옮겼다.

**배운 점**
- **계산과 해석을 나누면 신뢰가 생긴다.** 숫자를 코드가 만들자 AI가 틀릴 수 있는 범위가 "도구 선택과 설명"으로 좁아졌고, 정답을 손계산으로 검증할 수 있었다.
- **근거가 없는 변수는 숨기지 말고 축으로 드러낸다.** 자체발전 감소율은 근거 수치가 없어 결과를 크게 흔들었다. 빼면 쉬웠지만, 시나리오 축으로 밝히자 "경제성 증명"이라는 무리한 결론 대신 성립 조건을 말할 수 있었다.
- **외부 의견이 도구를 바꿨다.** "필요한 양과 부족한 양만 구하는 것으로는 부족하다, 어떤 조건을 바꿔야 하는지가 필요하다"는 검토 의견으로 부족분 해소 도구와 질문 3개가 추가됐다.
- **원문 확인이 숫자를 고친다.** 개편 요금 시간대는 기사 해석(9~15시 통일)이 한전 안내문과 달라 폐기했고, 전기로 감축 주장 350만 t은 경계가 불명확해 별도 시나리오로 분리했다.
- **아쉬운 점**: 투자비·원료비 자료를 확보하지 못했고, 평가가 마지막 단계로 밀렸다. 다음에는 평가 세트를 처음부터 개선용과 평가용으로 나눠 둔다.

### E-2. 시나리오 정의, 계산 예시, 모른다고 답할 것, 설계 주의

| S4G | S4 + 무탄소 100% | 순 저감 41.8만 t |
| S5 | S1 + S4 | 추가 1.57 TWh, 2,792억 원, 순 저감 311만 t |

**계산 예시(점검용)**: 전기로 가동률 100%·전량 구매 시 2.5Mt×0.45 = 1.125 TWh(현재 구매 3.05 TWh의 약 37%), 탄소 증가 1.125×0.4173 ≈ 46.9만 tCO2(2024 Scope 2의 약 34%), 요금 kWh당 약 181원 × 1.125 TWh ≈ 2,040억 원. 산업용 평균 판매단가 2025년 181.9원과 가깝지만 평균 대비라 독립 검증은 아니다.

**어시스턴트가 "모른다"고 답해야 하는 것**: 포스코 사내 실제 전력 계약·단가·설비별 사용량 / 2026 중간부하 단가(확인 전까지) / 로드맵 감축 목표(원문 확보 전까지) / 투자비, 시간대별 생산 지속 여부, 미래 요금 인상률.

**설계 주의(발표·어시스턴트 설계 때 그대로 밝힐 것)**
- 순 탄소는 Scope 1 감축(포스코 주장 기반)에 크게 의존한다. 순 탄소 불확실성의 66~82%가 고로 대체 비율(`bf_replace`)이다. 자체발전 감소로 부생가스 연소가 줄어 생기는 Scope 1 변화는 반영하지 않았다.
- 기본요금은 평균 전력÷부하율(0.8, 근거 없음)로 계약전력을 추정한다. UCI 분석은 한 해 최대를 12개월 모두에 적용했다.
- UCI는 낮 가동 소규모 사업장이라 제철소 대표가 아니고 방법 시연용이다. 평균 단가 계산에 달력·시간대 비중으로만 썼다.
- 몬테카를로는 변수 독립·균등(또는 삼각) 분포 가정이며, 비율은 가정한 분포의 표본 비율이지 현실의 확률이 아니다. 순위상관 점수는 분산 기여도가 아니라 영향 순서를 보는 용도다. 범주형(요금제)은 빠진다.
- **평가지표의 순환성**: 숫자 일치율의 정답이 시뮬레이터 출력이면 AI가 계산을 옮기는 정확도만 잰다. 시뮬레이터 자체의 타당성은 `analysis/05_검증.py`(내부 정합성 + 외부 대조)로 따로 보인다.
- 수소환원 전력 원단위·고로 배출 원단위는 유럽 논문과 포스코 평균에서 가져왔다. 고철 공급 한계, 설비 투자비, 수전해 부하의 유연성(시간대별 운전)은 반영하지 않았다.
- 배출계수 추세 직선(2010~2023 14점, 2018~2023 6점)은 예측이 아니라 시나리오 범위다. 2018은 온실가스 배출 정점 연도이지 계수의 전 기간 최고가 아니다. 기울기 95% 구간은 회귀 가정 하의 참고값이다.
- 수소환원이 전기로와 같은 저감을 내는 데 필요한 무탄소 비율은 경계 가정에 따른 두 시나리오다(상향식 약 83%, 포스코 1.4 t/t 기준 약 62%). 신뢰구간이 아니다.

### E-3. 외부 AI 검토(GPT-6 Astra) 8건과 우리의 조치

### E-5. 어시스턴트 입출력 명세

계산은 코드(`src/assistant_tools.py`의 `call_tool(이름, 인자)`), 해석은 AI. 반환은 항상 `{"status": ...}` JSON.

| 도구 | 용도 | 필수 인자 |
|---|---|---|
| `simulate` | 시나리오 계산(전력 TWh·탄소 tCO2·요금 억 원) | `eaf_mt` 또는 `h2_mt` |
| `required_output` | 목표 순 저감 → 필요 생산량·전력·요금 | `target_abate_t`, `path`(`eaf`/`h2`) |
| `min_green` | 수소환원 생산량·목표 → 필요 무탄소 비율·부족분 | `h2_output_mt`, `target_abate_t` |
| `sweep_green` | 한 조건만 바꿔 `min_green` 반복 | `h2_output_mt`, `target_abate_t`, `vary`, `values` |
| `close_gap` | 부족분을 0으로 만드는 조건을 하나씩 역산(레버 6개) | `h2_output_mt`, `target_abate_t`, `green_supply_twh` |
| `compare_paths` | 같은 목표를 네 경로로 달성할 때 비교 | `target_abate_t` |
| `breakeven_grid` | 수소환원 손익분기 전력배출계수 | 없음 |

**status별 답변 규칙**
- `ask`: `missing`을 사용자에게 되묻는다. 추측해서 채우지 않는다. 생산 규모와 목표는 기본값 없이 반드시 묻는다.
- `refuse`: `reason`과 함께 답변을 유보한다(허용 범위 밖, 모르는 변수, 모르는 도구). 범위 밖 값을 임의로 바꿔 계산하지 않는다.
- `ok`: `result`의 숫자만 인용한다. `defaults_used`는 가정으로 밝히고 `sources`로 출처를 붙인다.
- 도구가 없는 질문(미래 예측, 사내 데이터, 투자비, 실제 배출권 회피액, 미확정 요금, 미래 요금 인상률)은 도구를 부르지 않고 근거 부족으로 거절한다. 실제 회피액 질문은 거절하되 가정 가격을 주면 참고 가치는 계산할 수 있다고 안내한다.
- 부족분이 있으면 되묻지 말고 `close_gap`으로 "무엇을 얼마나 바꾸면 메워지는가"를 보여 준다. 확보량을 모르면 먼저 묻는다.

**항상 밝힐 한계**: 부족분은 연간 전력량 기준(`note`를 그대로 붙임), 수치는 예측이 아닌 조건부 계산값, 전기로·수소환원은 같은 경계로 비교하고 포스코 1.4 t/t는 `eaf_basis="posco_net"`일 때만, 배출권 가치는 참고 가치, 요금은 전력 요금만.

### E-6. 웹 앱 연결 가이드

계산 로직은 완성되어 있으므로 웹 앱은 화면과 연결만 만든다. 숫자를 JS 등에서 다시 계산하지 않는다.
- **호출 방법 3가지**: (A) 파이썬 `call_tool("simulate", {...})` 직접 호출(입력칸 계산용, 오류가 예외 대신 status로 옴), (B) 명령줄 `python3 -m src.assistant_cli 도구이름 '{json}'`(JSON 한 줄 출력, 다른 언어 서버용), (C) `analysis/13_어시스턴트_ClaudeCode.py`의 `ask("질문")`(채팅, 개발자 PC에서만 동작, 응답 십수 초).
- **응답 처리**: `ok`는 숫자와 `defaults_used`를 표시, `ask`는 `missing`에 해당하는 입력칸을 요구, `refuse`는 사유를 그대로 표시하고 값을 고쳐 재계산하지 않는다.
- **입력 범위**: 슬라이더 범위를 허용 범위에 맞추면 오류가 거의 없다(예: `eaf_mt` 0~2.5, `eaf_util` 0.3~1, `h2_mt` 0~2.5, `h2_green` 0~1, `grid_factor` 0.20~0.56, `ets_price` 1만~3만, `selfgen_cut` 0~0.3).
- **화면에 넣을 문구**: ① 예측이 아닌 조건부 시나리오 ② 부족분은 연간 전력량 기준이며 생산 지속 여부를 판단하지 않음 ③ 요금은 전력 요금만 ④ 배출권 가치는 참고 가치 ⑤ 사내 실제 데이터는 쓰지 않음 ⑥ `defaults_used`는 가정한 기본값
- **하지 말 것**: 숫자 재계산, 범위 밖 입력 임의 보정, 새 폴더 생성(프로젝트 규칙 5개 폴더만), API 키를 코드·git에 넣기.
- 준비: 프로젝트 루트에서 실행, `data/Steel_industry_data.csv`는 저장소에 포함, `python3 analysis/05_검증.py`가 "검증 완료"면 환경 정상.

### E-7. 현업 확장안: 사내망·온프레미스 LLM으로 옮긴다면

우리는 포스코 사내 시스템과 사내 LLM의 사양을 모른다. 아래는 **가정을 둔 설계**이며 "확인된 사내 사양이 아니라 확장 방향"이라고 밝힌다. 결론: **LLM 연결부만 사내 모델로 바꾸고 계산기와 평가 세트는 그대로 가져간다.**

| 구성 | 사내 확장 시 | 이유 |
|---|---|---|
| 계산기(`simulator`, `target`) | 그대로 | 외부 의존이 적은 순수 계산 코드 |
| 되묻기·거절·답변 규칙 | 그대로 | 모델과 무관한 규칙 |
| 질문 33개와 자동 채점 | 그대로, 더 중요해짐 | 모델을 바꿀 때 같은 시험으로 다시 확인하는 수락 시험 |
| LLM 연결부 | 교체 | 사내 LLM 호출 방식에 맞춰 어댑터 한 곳만 수정 |
| 시스템 프롬프트 | 재조정 | 모델이 바뀌면 되묻기·거절 습관이 달라져 평가로 다시 맞춤 |

| 지금(공개 자료) | 사내 확장 시(가정) |
|---|---|
| UCI 부하, 한전 공개 요금표 | 설비별 실제 15분 부하, 실제 계약 요금제와 청구 내역 |
| 문헌값 전력 원단위(3,720 kWh/t 등) | 설비 실측 원단위 |
| 전국 평균 배출계수(0.4173) | 사내 실제 전력 조달 구성과 배출량 산정 기준 |
| 사용자가 입력하는 무탄소 확보량 | 실제 PPA(전력구매계약)와 자체 발전 계획 |

- **장점**: 전력 계약·생산 계획 같은 민감 정보가 밖으로 나가지 않고 비용이 고정이다. **위험**: 사내 모델이 작으면 한국어 이해와 도구 호출 정확도가 떨어질 수 있다. 그래서 "숫자는 코드가 책임지고 AI는 이해와 설명만"이라는 원칙이 더 중요하다. 도구 호출을 지원하지 않는 모델이면 "모델이 JSON을 출력하고 코드가 해석해 도구를 실행"하는 방식으로 바꾼다.
- **필요한 것**: ① 시간대별 모델(15분 단위 부하·공급을 반영하면 "멈추지 않고"와 직결) ② 사내 규정·계약서·배출권 할당 자료의 근거 검색과 인용 ③ 계산 기록·재현·접근 권한 ④ 사람이 최종 판단
- **로드맵**: 1 시제품(지금, 공개 자료) → 2 사내 시험(사내 LLM으로 교체, 같은 질문 33개 수락 시험) → 3 병행 운영(실제 데이터를 읽기 전용으로 연결해 기존 계획과 나란히 비교만, 의사결정에는 미사용) → 4 도입(신뢰가 쌓인 뒤 의사결정 지원 도구)
- 발표용 한 문장: "계산과 AI를 분리해 두었기 때문에, 사내 LLM으로 교체해도 계산기와 평가 세트는 그대로 쓰고, 실측 데이터로 바꾼 뒤 병행 운영으로 신뢰를 쌓아 도입할 수 있다."

### E-8. 사용자, 입출력, 사용 상황, 용어

- **프로젝트 한 문장**: 전기로·수소환원제철로 바꿀 때 필요한 전력과 무탄소 전력을 한국어 질문으로 계산해 주고, 숫자의 가정과 출처, 한계까지 설명하는 AI 도우미.
- **사용자(우리가 제안, 현업 인터뷰로 확인하지 못함)**: 설비 전환 계획 담당자(생산량·감축 목표를 정함), 에너지 조달 담당자(확보 가능한 전력량을 앎). 두 사람이 같은 도구로 "목표를 맞추려면 전기가 얼마나 필요하고 확보한 것으로 부족한가"를 본다.

| 사용자가 넣는 것 | 도구가 내놓는 것 |
|---|---|
| 생산량(예: 수소환원 연 50만 t) | 필요한 전력(1.86 TWh) |
| 탄소 감축 목표(예: 순 저감 50만 t) | 필요한 무탄소 전력 비율과 양(36%, 0.67 TWh) |
| 확보 예정 무탄소 전력(예: 0.5 TWh) | 부족분(0.17 TWh) |
| 바꿔 보고 싶은 조건(전력 원단위, 배출계수) | 조건별 비교, 전기요금, 가정과 출처, 한계 |

- **돕는 결정**: 전환 규모에 맞춘 전력 확보 목표 설정, 무탄소 전력을 더 확보할지와 조건 변경 효과 검토, 전기로·수소환원 중 먼저 검토할 쪽 비교(보조 기능). 참고 자료이지 최종 판단이 아니며 투자비, 시간대별 공급, 사내 실제 데이터, 미래 예측은 다루지 않는다.
- **대표 흐름**: ① 목표 설정(생산량·감축 목표) → ② 필요 조건 계산(`min_green`) → ③ 확보 계획과 비교해 부족분 → ④ 대안 검토(`sweep_green`, 부족분을 메우는 조건은 `close_gap`). 이 흐름은 사용자가 입력한 목표와 수소환원 쪽 값(3,720 kWh/t, 고로 1.99 t/t)만 쓰므로 전기로 직접 배출(2차 출처 0.08)이나 포스코 주장(1.4 t/t, 경계 미확인)에 의존하지 않는다.
- **제출 결과물 4종**: 프로젝트 기획서(제출 완료), 소스코드, 결과보고서·발표자료, 시연 영상. 평가 기준은 아래 용어와 함께 1장의 성공 기준을 따른다.
- **용어 보충**: **합탕** = 전기로 쇳물과 고로 쇳물을 섞어 쓰는 기술(광양 전기로가 사용). **무탄소 전력** = 우리 계산에서는 이 전기에 대해서만 탄소를 0으로 친다(태양광·원전 구분 없음). **전력망 전력** = 여러 발전이 섞인 일반 전기로 1 MWh당 평균 0.4173 t. **순 탄소 저감** = 고로를 줄여 없앤 탄소에서 새로 쓰는 전기를 만들며 나오는 탄소를 뺀 값.
- **항상 함께 말할 한계**: 공개 자료 기반 조건부 계산(예측 아님, 실측 아님), 부족분은 연간 전력량 기준, 요금은 전력 요금만, 전기로 대 수소환원 비교는 계산 기준 가정에 따른 시나리오.
